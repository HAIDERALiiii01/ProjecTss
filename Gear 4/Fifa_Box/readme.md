## 🎯 What it does

Fifa_Box is a RAG (Retrieval-Augmented Generation) assistant that answers questions about FIFA World Cup history — winners, records, iconic moments, stats — grounded in a real knowledge base rather than guesswork. It combines vector search, keyword search (BM25), query rewriting, and cross-encoder reranking to pull the most relevant facts before generating an answer.

The desktop app wraps this in a browser-style card archive: **Winners** and **Moments** rails you can browse and click into, plus a slide-in chat drawer ("Press Box") wired directly into the retrieval pipeline.

## ⚙️ How it works

1. **Ingestion** — `ingest.py` loads every document in `knowledge-base/`, splits each into overlapping chunks using an LLM (with a headline + summary + original text per chunk), embeds them with `text-embedding-3-large`, and stores everything in a persistent Chroma collection.
2. **Query rewriting** — when you ask a question, `answer.py` first rewrites it into a short, search-optimized query.
3. **Hybrid retrieval** — it runs both dense vector search and BM25 keyword search, on the original *and* rewritten question, and merges the results.
4. **Reranking** — a cross-encoder (`ms-marco-MiniLM-L-6-v2`) reranks the merged candidates against your original question.
5. **Generation** — the top chunks are stuffed into context and passed to the LLM to produce a grounded answer.
6. **UI** — the pywebview desktop shell calls `answer_question()` directly (no separate API server) and renders the answer, with source documents, in the chat drawer.

## 🚀 Getting started

### 1. Clone the repository
```bash
git clone https://github.com/HAIDERALiiii01/Fifa_Box
cd Fifa_Box
```

### 2. Create a virtual environment
```bash
python -m venv venv
venv\Scripts\activate       # Windows
source venv/bin/activate    # macOS/Linux
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

### 4. Set up your `.env` file
Create a file named `.env` in the project root (same level as `app/`) with your OpenAI key:
```
OPENAI_API_KEY=sk-your-key-here
```
This is read automatically via `python-dotenv` — never commit this file. Make sure `.env` is listed in your `.gitignore`.

### 5. Build the knowledge base (first run only)
```bash
python app/pro_implementation/ingest.py
```
This chunks everything in `app/knowledge-base/` and builds the vector store at `app/preprocessed_db/`. Re-run this any time you add or change source documents. If you hit rate limit errors, drop `WORKERS` to `1` inside `ingest.py`.

### 6. Launch the app
```bash
python ui/main.py
```
A desktop window opens. Browse Winners and Moments, or click **Ask the archive** to open the chat.

## 🖼️ Adding your own media (optional)

The UI works out of the box with generated placeholder art — no images required. To use real photos/gifs, drop files into `ui/assets/winners/<id>/` or `ui/assets/moments/<id>/` (matching the `id` field in the JSON files) as `poster.jpg`, `gif.gif`, and `gallery/1.jpg`, `2.jpg`, etc. Full naming convention is in `ui/assets/README.md`.

---

## 🧪 Evaluating answer quality (optional)

```bash
python app/evaluation/eval.py
```
Runs the pipeline against `app/evaluation/tests.jsonl` to check retrieval and answer accuracy.

## 📦 Requirements

Install everything with:
```bash
pip install -r requirements.txt
```

Key libraries used:
- `openai` — embeddings (`text-embedding-3-large`)
- `litellm` — LLM completions (query rewriting, chunking, answer generation)
- `chromadb` — persistent vector store
- `rank_bm25` — keyword search
- `sentence-transformers` — cross-encoder reranking
- `pydantic` — structured chunk/output schemas
- `python-dotenv` — loads `.env`
- `pywebview` — desktop UI shell

---

## 📝 Notes

- Run `ingest.py` once before the first launch — the app has nothing to answer from until the vector store exists.
- Re-run `ingest.py` whenever you add or edit files in `knowledge-base/`.
- The UI has no backend server — `ui/main.py` calls `answer_question()` in-process, so the whole app is just one Python process plus a webview window.
- Keep your `.env` out of version control.
